# Verification — range-based constraint
#
# Input   : the alignment scaffold (one image) and this text.
# Model   : VLM (1 image + text)
# Output  : YES / NO, read out of "Status: [...]"
# Paper   : Section VI-C and Section VII-B (the reference-calibrated grid)
# Code    : cascade/question.py :: build()
#
# The difference from the composition case is where the comparison happens.
# The normal range is computed in code from the K references at calibration
# time and written into the question as an integer range. The model is never
# asked to measure the references, and never asked whether something looks
# right. It is asked to read one coordinate off the overlay and say whether it
# falls in a stated range -- which is the whole point of the alignment
# scaffold: an unstable measurement becomes a repeatable reading.
#
# Because the range is already stated, the question has no natural-language
# form to fall back on. Its shape follows the edge type Stage 3 settled on:
#
#   horizontal    a single fill line       "Is the {target} level positioned
#                                           at row A~B?"
#   rectangular   a placed rigid object    "Does the {target} occupy
#                                           row_start=A~B, row_end=C~D,
#                                           col_start=E~F, col_end=G~H?"
#   contour       a self-contained extent  "Does the {target} occupy A~B tick
#                                           marks?"
#
# A~B collapses to a single number when the references agree exactly. When no
# calibrated range is available the builder falls back to the plain
# interrogative, which is the composition-style question without a range.
#
# TWO TEMPLATES, because there are two rulers and they are read differently.
# A grid is *read* -- the model finds the labelled intersection nearest the
# edge and reports its row. Ticks are *counted* -- the model counts the marks
# lying along the object. Telling a model to count the marks on a grid, or to
# read a row off a row of ticks, describes an image it was not given; the
# builder picks the section matching the scaffold that was actually drawn.
#
# The **Visual Cues** block likewise describes only marks that were drawn.
# The instruction against reading background patterns as the overlay is there
# because several of these products are photographed on mesh or inside a
# plastic bag, and a regular background texture is easy to mistake for it.
#
# Answer convention: YES means the reading fell in the calibrated range, so
# YES is normal, and code inverts it the same way as the composition case.
#
